### Two failures CI caught before release

CI's first run failed, which is the point of having it:

1. The suite only ran where the package had been installed editable by hand, so
   a fresh checkout could not run pytest at all. Fixed by declaring
   `pythonpath` in `pyproject.toml`; verified in a virtualenv containing only
   pytest, where importing the package fails but all 626 tests pass.
2. The install job called the environment's scripts by absolute path without
   putting its `bin` on `PATH`, so `harness.entry_points` correctly reported
   `ACTION_REQUIRED`. The check was right; the step was wrong.

## 5. Live acceptance

Not performed. This release is verified non-live. No runtime, provider,
credential store, or model was contacted and no managed run was started.

Live acceptance remains a separately authorized operator action. The most recent
sealed live evidence is `run-20260806-194307-801b42`, recorded in
`docs/status.md`, and this release does not change its meaning: plan hashes and
recorded `input_hashes` keys are unchanged, so it stays comparable with future
runs.

## 6. Rollback

| Item | Result |
| --- | --- |
| Rolling back requires no change to existing sealed evidence | PASS |
| Rolling back requires no re-run of a completed evaluation | PASS |
| Packaging change reversible without rewriting plan hashes | PASS, hashes never changed |

**Honest limitation:** there is no working prior release to roll back *to*. No
tags existed before `v0.4.0`, and an installed copy of the pre-0.4.0 code
crashed on `lmre --help` — that crash is one of the defects this release fixes.
Rollback therefore means checking out an earlier commit and using the `./bin/`
wrappers, not reinstalling an earlier package.

Rollback trigger: any evidence that plan hashes or `input_hashes` keys changed,
or that sealed bundles stopped verifying. Decision owner: the repository owner.

## Known gaps carried into the release

- No pinned linter configuration, so CI runs no linter and the "new modules
  clean" convention stays manual.
- No whitespace check in CI; the whole-tree form fails on intentional Markdown
  hard line breaks.
- Not published to a package index. The README documents installing from the
  repository git URL instead, which was verified end to end: a clean virtualenv
  installs 0.4.0 from `git+https://...` and `lmre --help` succeeds. Publishing
  to an index remains a separate decision.
